**PART 2: Build a dynamic Form Builder feature for the admin portal**

Purpose: let the admin create, edit, and manage multiple forms (Careers, future forms like Admissions, Event Registration, etc.) without needing code changes. Each new form automatically becomes its own live page at a chosen URL — no separate page-building step needed.

**2a. Database schema**
- `forms` table: `id`, `title`, `slug` (URL path, e.g. "careers"), `description`, `is_active`, `created_at`
- `form_fields` table: `id`, `form_id` (FK), `label`, `field_type` (text, textarea, number, date, dropdown, checkbox_group, radio, file_upload), `options` (JSON array, for dropdown/checkbox/radio choices), `is_required`, `display_order`, `conditional_logic` (JSON, optional — e.g. "only show if field X = value Y")
- `form_submissions` table: `id`, `form_id` (FK), `submitted_at`, `data` (JSON — stores all field responses keyed by field label/id), `file_paths` (JSON, for any uploaded files)

**2b. Admin UI — Form Builder**
- List view: all forms created, with Active/Inactive toggle, Edit, Delete, "View Submissions" buttons
- "Create New Form" button — prompts for Title + URL slug (this slug becomes the live page URL automatically, e.g. `/admissions`)
- Form editor page:
  - Add Field button — choose field type, label, required toggle, options (for dropdown/checkbox/radio)
  - Reorder fields via drag-and-drop
  - Delete field button per field
  - Conditional logic option: "Show this field only if [other field] = [value]"
  - Save/Publish button

**2c. Public-facing form renderer**
- Dynamically renders whatever form matches the URL slug — creating a new form automatically creates its page, no manual page coding needed
- Renders fields in `display_order`, respecting `is_required` and `conditional_logic`
- On submit, saves response into `form_submissions`, with file uploads stored in file storage and paths saved in `file_paths`
- Shows thank-you confirmation message after submit

**2d. Admin — View Submissions**
- Table view per form, sortable/filterable by any field
- Export to CSV button
- Mark submission as Reviewed / Shortlisted / Rejected (status field)

**2e. Migrate the existing Careers form**
Once the form builder is working, migrate the Careers form (from Part 1) into this new system as the first form entry, so it's managed the same way as future forms.

**2f. Technical notes**
- Keep consistent with existing stack: Node.js/Express, PostgreSQL, Drizzle ORM, React/TypeScript
- Mobile-responsive on both admin builder and public-facing forms
- Reuse existing file upload handling for the file_upload field type
